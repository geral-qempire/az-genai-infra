## 1. Template

Provision a Key Vault with pre-configured tiers for normal or high-load workloads. Includes secure defaults (private endpoint, RBAC authorization, monitoring alerts) and RBAC profiles for tech leads and developers.

**Note:** This template expects an existing Resource Group. The Resource Group should be created separately before deploying this stack.

**Available Tiers:**
- **Tier 1 (Standard)**: Normal workloads, suitable for most projects including production
- **Tier 2 (Premium)**: High-load workloads with enhanced security features (HSM-protected keys)

## 2. Usage

```hcl
module "key_vault_tiers" {
  source = "../../stacks/key_vault_tiers"

  providers = {
    azurerm     = azurerm
    azurerm.dns = azurerm.dns
  }

  # Context
  resource_group_name = "rg-we-acme-dev" # Existing Resource Group (created by automation)
  service_prefix      = "acme"
  location            = "westeurope"
  tenant_id           = "00000000-0000-0000-0000-000000000000"
  environment         = "dev"
  tags                = { env = "dev", owner = "security-team", costcenter = "CC1234" }

  # Tier Selection
  tier = "tier1" # Options: "tier1" (standard) or "tier2" (premium)

  # Networking for Private Endpoint
  subnet_name              = "snet-priv-endpoints"
  vnet_name                = "vnet-hub"
  vnet_resource_group_name = "rg-we-platform-networking"
  dns_resource_group_name  = "rg-we-platform-networking"

  # RBAC - User Profiles
  ad_read_group_id = "22222222-2222-2222-2222-222222222222" # Developers group ID
  ad_full_group_id  = "33333333-3333-3333-3333-333333333333" # Tech leads group ID

  # Action Group (Optional)
  action_group_enabled = true
  action_group_emails  = ["alerts@contoso.com"]
  # OR use existing action group:
  # action_group_id = "/subscriptions/xxx/resourceGroups/rg-monitoring/providers/Microsoft.Insights/actionGroups/ag-alerts"
}
```

## 3. Tiers Configuration

### Tier 1 (Standard) - Normal Workloads

**Key Vault Settings:**
- SKU: `standard`
- Soft Delete Retention: `90 days`
- Purge Protection: `enabled`
- Public Network Access: `disabled`
- RBAC Authorization: `enabled`
- Network ACLs Bypass: `AzureServices`
- Private Endpoint: `enabled`
- Default Alerts: `enabled` (Availability and Saturation)

**RBAC Roles:**
- **Tech Leads**: Key Vault Certificates Officer, Key Vault Crypto Officer, Key Vault Secrets Officer, Reader
- **Developers**: Key Vault Certificate User, Key Vault Crypto User, Key Vault Secrets User, Reader

### Tier 2 (Premium) - High-Load Workloads

**Key Vault Settings:**
- SKU: `premium` (supports HSM-protected keys)
- Soft Delete Retention: `90 days`
- Purge Protection: `enabled`
- Public Network Access: `disabled`
- RBAC Authorization: `enabled`
- Network ACLs Bypass: `AzureServices`
- Private Endpoint: `enabled`
- Default Alerts: `enabled` (Availability and Saturation)

**RBAC Roles:**
- **Tech Leads**: Key Vault Certificates Officer, Key Vault Crypto Officer, Key Vault Secrets Officer, Reader
- **Developers**: Key Vault Certificate User, Key Vault Crypto User, Key Vault Secrets User, Reader

## 6. User Profiles and RBAC Roles

### Tech Leads Profile (ad_full_group_id)

The following roles are assigned to the tech leads group:

| Role | Scope | Description |
|------|-------|-------------|
| Key Vault Certificates Officer | Key Vault | Full certificate management (create, read, update, delete, list certificates) |
| Key Vault Crypto Officer | Key Vault | Full key management (create, read, update, delete, list keys; import keys; perform crypto operations) |
| Key Vault Secrets Officer | Key Vault | Full secret management (create, read, update, delete, list secrets) |
| Reader | Key Vault | Read metadata about the Key Vault resource |

### Developers Profile (ad_read_group_id)

The following roles are assigned to the developers group:

| Role | Scope | Description |
|------|-------|-------------|
| Key Vault Certificate User | Key Vault | Read and list certificates; use certificates for TLS/SSL operations |
| Key Vault Crypto User | Key Vault | Use keys for cryptographic operations (encrypt, decrypt, sign, verify) |
| Key Vault Secrets User | Key Vault | Read and list secrets (cannot modify or delete) |
| Reader | Key Vault | Read metadata about the Key Vault resource |
